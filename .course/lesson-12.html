1. One permission, two operating systems

Both platforms follow the same loop. Android's guide puts it in steps: "Check whether the user has already granted runtime permission your app requires", then, if not, "Request the runtime permission", then "Check the user's response", and "If the user denied the permission instead, gracefully degrade your app experience" (Request runtime permissions). It adds a rule worth remembering: "You must check whether you have a permission every time you perform an operation that requires that permission", because the user can change it in Settings at any time. Apple says the same: "Because a person can change authorization at any time using Settings, always check the authorization status of a feature before accessing it" (Requesting access to protected resources).

The app core can't speak in any of those terms: they belong to the platforms. So it gets its own words, chosen for what the user can do next, and each adapter translates. That's the rule from Lesson 10: an outbound port is named in the app's terms.

  1. NotRequested: asking will show the system prompt. That's iOS's notDetermined, "the user has yet to authorize Bluetooth for this app".
  2. Denied: refused, but the system will still show its prompt. Only Android has it. Android's guide asks you to explain why first: "If this method returns true, show an educational UI to the user", where "this method" is shouldShowRequestPermissionRationale().
  3. PermanentlyDenied: refused, and no prompt will appear again. On Android that's the second refusal ("The user's action implies "don't ask again," and is considered a permanent denial"). On iOS it's the first: "If the person denies permission, the access attempt that initiates the prompt, and any further attempts, fail", and the system "doesn't prompt again" (Requesting access to protected resources). So iOS's denied maps to PermanentlyDenied, not to Denied.
  4. Restricted: iOS's restricted: "the user can't change the Bluetooth authorization status, possibly due to active restrictions such as parental controls". The app can only say so.
  5. Granted: Scan is enabled. It can still change: the user can turn the permission off in Settings (Android then reports Denied, iOS PermanentlyDenied), which is why every screen re-reads it when the app comes back to the foreground (section 8).

3. Declare before you ask

Neither OS will ask for a permission the app hasn't declared. On Android, the declarations go in the manifest, the same on both Android tracks:

  1. maxSdkVersion="30" on the old permissions: "This app compatibility step helps the system grant your app only the Bluetooth permissions that it needs when installed on devices that run Android 12 or higher" (Bluetooth permissions). BLUETOOTH and BLUETOOTH_ADMIN are granted at install time. ACCESS_FINE_LOCATION is the runtime one the adapter asks for on Android 11 and lower.
  2. BLUETOOTH_SCAN and BLUETOOTH_CONNECT are runtime permissions: "When your app requests at least one of these permissions, the system prompts the user to allow your app to access Nearby devices". Scanning needs the first one (Lesson 13), and connecting needs the second (Lesson 14). One dialog covers both.
  3. neverForLocation is a promise that the app never works out where the user is from scan results, so Android 12+ doesn't need location. It has a cost: "If you include neverForLocation in your android:usesPermissionFlags, some BLE beacons are filtered from the scan results." The Device Monitor connects to peripherals and doesn't track beacons, so the promise is true and the cost doesn't matter.

The adapter maps the app's Permission.Bluetooth to Android's names, which depend on the Android version:

Then check. Android's own API answers only "granted or not": "This method returns either PERMISSION_GRANTED or PERMISSION_DENIED". Telling NotRequested, Denied and PermanentlyDenied apart takes two more clues:

  1. isGranted is ContextCompat.checkSelfPermission(context, name) == PERMISSION_GRANTED, for every Android name the app permission maps to.
  2. shouldShowRationale asks ActivityCompat.shouldShowRequestPermissionRationale(activity, name), which needs an Activity: section 5 is where the adapter gets one. Without one it answers false here, and a Denied permission would read as PermanentlyDenied (refusal remembered) or NotRequested (none remembered). So both Android tracks lend the Activity before anything reads the status (sections 5 and 8). Its documentation says only "Gets whether you should show UI with rationale before requesting a permission". It doesn't say when it answers false, so we watched (table below).
  3. refusals is the adapter's memory. "Not granted, and no rationale" means two different things: never asked, or refused for good. Android can't tell them apart, so the adapter remembers, in SharedPreferences, every permission it has seen refused. A memory of refusals is the adapter's job, not a rule of the app: iOS needs none.

5. Android: lending the adapter a launcher

Here's the one exception to "only the adapter talks to the OS". Android shows its dialog through the Activity Result API, and only an Activity or a Fragment can register for a result: "You must call registerForActivityResult() before the fragment or activity is created", and "the callback must be unconditionally registered every time your activity is created" (Get a result from an activity). The adapter lives for the whole process; activities and fragments come and go. So the UI code registers the launcher and lends it to the adapter, with the Activity the rationale needs (section 4). It decides nothing: it doesn't check, launch or read the answer.

  1. detach checks it's the same launcher. If a newer Activity or Fragment has attached its own launcher meanwhile, the old one's detach leaves it alone instead of wiping it.
  2. No Activity is kept after detach: the adapter lives as long as the process, and holding a destroyed Activity would leak it.
  1. A property initializer is the safe place: "registerForActivityResult() is safe to call before your fragment or activity is created, letting it be used directly when declaring member variables" (Get a result from an activity). A rotation creates a new MainActivity, which registers again, as the rule asks, and its callback passes that new Activity to onResult.
  2. attach comes before setContent, because the first read of the permission happens in the content it composes: koinViewModel() builds the list screen's ViewModel when the screen is first composed, and the ViewModel's constructor reads the status (section 8). Attached first, that read already has the Activity, so it can tell Denied apart.
  3. onCreate/onDestroy bracket the Activity's whole life, so the adapter never holds a destroyed one. Its application is our DeviceMonitorApplication, which owns the adapter (section 7); by lazy reads it only when onCreate first needs it. Android's manual DI page reaches its container the same way: (application as MyApplication).appContainer.
Gotcha · a composable lends too late for the first read Compose has its own launcher: "The same Activity Result API and rememberLauncherForActivityResult() explained above can be used to request runtime permissions using … RequestMultiplePermissions contract for multiple permissions" (Compose and other libraries). Our first version used it, in a composable inside the list screen that attached the adapter in a DisposableEffect. That effect ran only after the screen had been composed, and composing it had already built the ViewModel, whose constructor read the status with no Activity attached. That read answers PermanentlyDenied or NotRequested for a Denied permission (section 4), and the screen shows it until ON_RESUME reads the status again. It's a race: on the API 36 emulator, two of our four screen recordings of a cold start after one refusal showed "Bluetooth permission is off" + Open Settings for the first frames, then "denied" + Ask again. After turning the permission off in Settings, the adapter remembers no refusal, so the wrong row is "needs Bluetooth permission" + Allow Bluetooth. With MainActivity lending before setContent, every cold start we recorded, after one refusal and after turning it off in Settings, showed "denied" + Ask again from the first frame.
  1. A property initializer is the safe place: "registerForActivityResult() is safe to call before your fragment or activity is created, letting it be used directly when declaring member variables" (Get a result from an activity). Every new Fragment instance registers again, as the rule asks.
  2. by lazy for the adapter, because requireActivity() throws until the Fragment is attached to its Activity, and property initializers run before that.
  3. onStart/onStop bracket the time the screen is visible, which is when a user can tap "Allow Bluetooth".

XML vs Compose · what changed and whyThe same three calls, attach, onResult and detach, in different homes. The XML track's screen is a Fragment, which can register for itself: it registers once per instance, as a property, and brackets the visible time with onStart/onStop. A Compose screen is a composable, which can't lend before it is composed, so the one Activity registers, as a property too, and brackets its whole life with onCreate/onDestroy. Either way, the Activity is attached before the screen's ViewModel first reads the status (section 8).

We rotated the emulator while the dialog was up, on both tracks (API 36). The Activity behind the dialog was recreated (logcat: finishDrawing of relaunch: … MainActivity). The answer was still delivered to the launcher the new Activity (Compose) or Fragment (XML) registered, and the screen showed "allowed" or "denied" as answered. The ViewModel and the adapter both outlived the old Activity, so the coroutine waiting in request got its answer.

6. The iOS adapter, in Swift

The iOS adapter is a Swift class in the iOS app that implements the Kotlin interface PermissionChecker. Swift sees a Kotlin interface as a protocol, so this is protocol conformance, and Koin hands the object to the app core like any other adapter. It's shared by both iOS tracks:

  1. CBManager.authorization is a class property: "The current authorization status for using Bluetooth". It can be read "before creating a CBManager instance", and "The initial value of this property is notDetermined" (CBManager.authorization). Reading it never prompts.
  2. Permission and PermissionStatus arrive as Swift enums, even inside the protocol's requirements: SKIE "generat[es] a wrapping Swift enum for a given Kotlin enum" and "adds back the exhaustive checking" (SKIE: Enums). So the switch returns .granted and friends directly.
  3. @unknown default handles a case a future iOS might add. .restricted is the cautious choice: the app shows "not available" and never prompts.
  4. @MainActor plus @preconcurrency. The adapter keeps mutable state, and Core Bluetooth calls its delegate on the main queue (queue: nil, below), so the class is main-actor isolated. The Kotlin protocol says nothing about actors, and Swift 6 refuses a main-actor method as a witness for it. @preconcurrency on the conformance accepts it, and Swift checks at run time instead: "Calling an isolated synchronous function from outside the isolation domain will result in a runtime error that halts program execution" (SE-0423). Our calls come from the ViewModel on the main thread, so the check holds.
  1. Why __request? Kotlin's suspend fun request reaches Objective-C as a method with a completion handler. SKIE then adds an async Swift function named request(permissions:) for calling it, and "renames the original suspend function by adding the __ prefix. This is done to avoid name collisions with the generated wrapper" (SKIE: Suspend functions). To implement it, write the original. The compiler accepts it as an async throws function, because suspend functions "always have an NSError*/Error parameter in the completion handler" (Interoperability with Swift/Objective-C).
  2. The prompt comes with the first use of Bluetooth. Apple: "The first time your app attempts to access a protected resource, the system prompts the person using the app for permission" (Requesting access to protected resources). iOS has no "request Bluetooth permission" call, so the adapter makes that first use by creating a CBCentralManager.
  3. withCheckedContinuation suspends until the delegate hears back. It's the one-value relative of Lesson 02's AsyncStream continuation: the closure gets a handle, and one resume() ends the wait ("You must call a resume method exactly once on every execution path", CheckedContinuation). centralManagerDidUpdateState is called whenever the manager's state changes, and Apple says to "Check this property [authorization] in your implementation of the delegate methods centralManagerDidUpdateState(_:)". Once it isn't notDetermined any more, the user has answered, so every waiting request resumes.
  4. CBCentralManagerOptionShowPowerAlertKey: false: by default "the system warns the user if the app instantiates the central manager when Bluetooth service isn't available" (docs). This manager exists only to ask for the permission, so it shouldn't nag about Bluetooth being off. Lesson 13's scanner creates its own.
  5. openSettingsURLString is "The URL string you use to deep link to your app's custom settings in the Settings app" (docs).
Gotcha · the Simulator always says yes We installed the app fresh on the iOS 26.2 Simulator and reset its privacy settings with xcrun simctl privacy booted reset all. CBManager.authorization still read .allowedAlways: the row said "allowed" and no prompt ever appeared. simctl privacy lists calendar, contacts, location, photos, the media library, the microphone, motion, reminders and Siri, but no Bluetooth service. 7. Wiring: each platform builds its own adapter

appModule stays platform-free. The platform adapter comes in through initKoin's parameter:

  1. Why a parameter? The Android adapter needs a Context, and the iOS one is a Swift object that Kotlin can't construct. Each platform builds its own and hands it over. The signature still has no Koin type, so Swift's header stays Koin-free (Lesson 11): it now declares doInitKoin(permissionChecker:).
  2. single { permissionChecker } registers the object under the parameter's type, PermissionChecker, which is what PermissionService(get()) asks for.
  3. platformModule is its own function so that the graph test can use the real one with a fake inside it (section 9).

The adapter is built in onCreate, where Lesson 11 starts Koin: it runs once, "when the application is starting, before any activity, service, or receiver objects (excluding content providers) have been created" (Application.onCreate). A property initializer would run earlier, in the constructor, before Android attaches the Application's Context, and the adapter opens its SharedPreferences as soon as it's built.

Koin keeps the Swift object for the life of the process, as a single. Nothing on the Swift side keeps a reference, and nothing needs to: on iOS no screen lends the adapter anything.

8. The ViewModel and the screens

The ViewModel gets the second inbound port and three new events. The UI state gets one field, bluetooth: PermissionStatus:

  1. The constructor reads the status, so the screen never shows a placeholder. On Android that read needs the lent Activity (section 4), and both tracks have it by then. On Compose, MainActivity attaches before setContent, and the ViewModel is built when the screen is first composed. On XML, the Fragment attaches in onStart and first touches its by viewModel() property when its repeatOnLifecycle(STARTED) block starts collecting, which is after onStart. On API 36, a cold start after one refusal, and one after turning the permission off in Settings, showed "denied" + Ask again from the first frame on both tracks (screen recordings).
  2. refreshPermission re-reads it, and every screen calls it when the app comes back to the foreground: the user may have changed it in Settings. It does nothing while a request is running, so it can't overwrite the answer that request is about to report.
  3. Koin needs no change for the new parameter: viewModelOf(::DeviceListViewModel) fills both with get().

Each screen shows one message and at most one button per status, enables Scan only for Granted, and re-reads the status when the app comes back to the foreground.

LifecycleEventEffect runs its block "when a specific event occurs" (Lifecycle and Compose), here every ON_RESUME. when over an enum is exhaustive, so a sixth status would fail to compile here until it has a row.

The layout gets a TextView (permissionText) and a borderless Button (permissionButton) between the filter and Scan, and Scan's top now hangs from the button. A GONE view in a ConstraintLayout collapses to a point, so Scan moves up when there's no action. render() is still the one place that touches views (Lesson 08).

scenePhase is Lesson 04's app-level lifecycle seen from a view. It becomes .active again when the user comes back from Settings.

UIScene.didActivateNotification "indicates that the scene is now onscreen and responding to user events", and Apple suggests it to "refresh the contents of views" (docs). The button's action reads viewModel.uiState.value.bluetooth when tapped and calls openSettings() for .permanentlyDenied, requestPermission() otherwise. The label and button sit in a vertical stack between the filter and Scan. A hidden view in a UIStackView takes no space.

UIKit vs SwiftUI · what changed and whySame messages, same rule for Scan, different ways to hear "back in the foreground". SwiftUI reads scenePhase from the environment and reacts with .onChange. UIKit observes UIScene.didActivateNotification with a selector. Both are scene-level events, Lesson 04's app-level lifecycle, because a screen's own viewWillAppear doesn't fire when the user returns from another app.

  1. Four tests, one per path through the rule: granted (no prompt), not requested (one prompt, the answer comes back), denied (asked again), permanently denied or restricted (no prompt, status unchanged).

Retrieval checks

Answer from memory, without scrolling up.

The user taps "Don't Allow" on iOS's Bluetooth prompt. Which status does the app core get?

iOS asks once: after the first attempt "the system remembers the person's permission choice and doesn't prompt again", so the only way back is Settings: that's what PermanentlyDenied means. Restricted is a policy the user can't change at all.

Why does the Android adapter keep a memory of refusals in SharedPreferences?

Android keeps the permission itself. What an app can't read back is whether the user refused it for good. A dismissed dialog and a second refusal look the same from the API, and only the adapter's memory tells them apart.

Which part of the app decides not to prompt for a permission that is Restricted?

"Prompt only when a prompt can appear" is a rule of the app, the same on both platforms, so it lives in the service, and neverPromptsWhenOnlySettingsCanChangeIt tests it. The screens hide the button too, but that's presentation.

Why does Android UI code touch the permission adapter at all?

Registration belongs to the Activity or Fragment and must happen every time one is created. It registers and lends the launcher; the adapter launches it and reads the answer.

On the Compose track, why does MainActivity call attach before setContent?

Without an Activity the adapter can't ask for the rationale, so a Denied permission reads as PermanentlyDenied or NotRequested. A composable that attaches in a DisposableEffect attaches only after that first read, and the wrong row can show for the first frames.

In Swift, why is the method named __request and not request?

SKIE generates request(permissions:) as an async function for callers, and "renames the original suspend function by adding the __ prefix". A Swift class implementing the Kotlin interface implements the original.

Mixed review (interleaved)

The ViewModel now takes two ports. What had to change in appModule for the ViewModel line? (Lesson 11)

viewModelOf takes the constructor reference. What had to be added is a binding for each new type it asks for: PermissionAccess, and the PermissionChecker its service needs.

// A permission the app needs, in the app's terms. Each platform's adapter maps it to its
// own: Bluetooth is two runtime permissions on Android 12 and later, one on iOS.
enum class Permission { Bluetooth }

// Where a permission stands, in terms of what the user can do next.
enum class PermissionStatus {
    NotRequested,      // not asked yet: a request shows the system prompt
    Denied,            // refused, and the app may ask again (Android only)
    PermanentlyDenied, // refused, and the system won't ask again: only Settings can change it
    Restricted,        // blocked by a policy the user can't change, such as parental controls (iOS)
    Granted,
}

package com.example.devicemonitor.core

import com.example.devicemonitor.core.inbound.PermissionAccess
import com.example.devicemonitor.core.outbound.PermissionChecker

// Service: the app's permission rules. Prompt only for what the system can still prompt
// for: never for a permission that is granted, permanently denied or restricted.
class PermissionService(private val checker: PermissionChecker) : PermissionAccess {
    override fun status(permission: Permission): PermissionStatus = checker.check(permission)

    override suspend fun request(permissions: List<Permission>): Map<Permission, PermissionStatus> {
        val before = permissions.associateWith { checker.check(it) }
        val askable = before.filterValues { it in ASKABLE }.keys.toList()
        if (askable.isEmpty()) return before
        return before + checker.request(askable)
    }

    override fun openSettings() = checker.openSettings()

    private companion object {
        val ASKABLE = setOf(PermissionStatus.NotRequested, PermissionStatus.Denied)
    }
}

// Inbound adapter: turns the screen's events into calls on the DeviceScanning and
// PermissionAccess ports, and the results into UI state. It knows the ports only.
class DeviceListViewModel(
    private val scanning: DeviceScanning,
    private val permissions: PermissionAccess,
) : ViewModel() {
    private val _uiState = MutableStateFlow(
        DeviceListUiState(bluetooth = permissions.status(Permission.Bluetooth)),
    )
    val uiState: StateFlow<DeviceListUiState> = _uiState.asStateFlow()

    private var scanJob: Job? = null
    private var permissionJob: Job? = null

    fun startScan(filter: String) {
        if (scanJob?.isActive == true) return
        _uiState.update { it.copy(scan = ScanState.Scanning(emptyList())) }
        scanJob = viewModelScope.launch {
            val found = mutableListOf<Device>()
            try {
                withTimeoutOrNull(SCAN_TIMEOUT) {
                    scanning.scan(filter).collect { device ->
                        found += device
                        _uiState.update { it.copy(scan = ScanState.Scanning(found.toList())) }
                    }
                }
                _uiState.update { it.copy(scan = ScanState.Finished(found.toList())) }
            } catch (e: ScanException) {
                _uiState.update { it.copy(scan = ScanState.Idle, errorMessage = e.message) }
            }
        }
    }

    fun errorShown() {
        _uiState.update { it.copy(errorMessage = null) }
    }

    // The screen calls this each time it comes back to the foreground: the user may have
    // changed the permission in Settings meanwhile.
    fun refreshPermission() {
        if (permissionJob?.isActive == true) return
        _uiState.update { it.copy(bluetooth = permissions.status(Permission.Bluetooth)) }
    }

    fun requestPermission() {
        if (permissionJob?.isActive == true) return
        permissionJob = viewModelScope.launch {
            val result = permissions.request(listOf(Permission.Bluetooth))
            _uiState.update { it.copy(bluetooth = result.getValue(Permission.Bluetooth)) }
        }
    }

    fun openSettings() {
        permissions.openSettings()
    }

    companion object {
        val SCAN_TIMEOUT = 3.seconds
    }
}

package com.example.devicemonitor.adapter.outbound

import android.Manifest
import android.app.Activity
import android.content.Context
import android.content.Intent
import android.content.pm.PackageManager
import android.net.Uri
import android.os.Build
import android.provider.Settings
import androidx.activity.result.ActivityResultLauncher
import androidx.core.app.ActivityCompat
import androidx.core.content.ContextCompat
import com.example.devicemonitor.core.Permission
import com.example.devicemonitor.core.PermissionStatus
import com.example.devicemonitor.core.outbound.PermissionChecker
import kotlinx.coroutines.CompletableDeferred

// Outbound adapter: Android's runtime permissions behind the PermissionChecker port.
// Android lets only an Activity or a Fragment register for a result, so one of them lends
// this adapter its launcher (attach), and tells it when the user answered (onResult).
class AndroidPermissionChecker(private val context: Context) : PermissionChecker {
    private var activity: Activity? = null
    private var launcher: ActivityResultLauncher<Array<String>>? = null
    private var answer: CompletableDeferred<Unit>? = null

    // Android has no "refused for good" status to read back, so the adapter remembers, across
    // launches, which permissions the user has refused.
    private val refusals = context.getSharedPreferences("permission-refusals", Context.MODE_PRIVATE)

    fun attach(activity: Activity, launcher: ActivityResultLauncher<Array<String>>) {
        this.activity = activity
        this.launcher = launcher
    }

    fun detach(launcher: ActivityResultLauncher<Array<String>>) {
        if (this.launcher !== launcher) return
        this.activity = null
        this.launcher = null
    }

    // The launcher's callback. It passes its own Activity too, so that whichever of attach and
    // onResult runs first after a rotation, the answer is read through the new Activity.
    fun onResult(activity: Activity) {
        this.activity = activity
        answer?.complete(Unit)
        answer = null
    }

    override fun check(permission: Permission): PermissionStatus {
        val names = permission.androidNames()
        return when {
            names.all { isGranted(it) } -> {
                refusals.edit().remove(permission.name).apply()
                PermissionStatus.Granted
            }
            // Refused before, and Android suggests explaining why: its dialog still shows.
            shouldShowRationale(names) -> {
                refusals.edit().putBoolean(permission.name, true).apply()
                PermissionStatus.Denied
            }
            // Refused before, and no explanation suggested any more: no dialog either.
            refusals.getBoolean(permission.name, false) -> PermissionStatus.PermanentlyDenied
            else -> PermissionStatus.NotRequested
        }
    }

    override suspend fun request(permissions: List<Permission>): Map<Permission, PermissionStatus> {
        val launcher = checkNotNull(launcher) { "No Activity or Fragment has attached a permission launcher." }
        val answered = CompletableDeferred<Unit>()
        answer = answered
        launcher.launch(permissions.flatMap { it.androidNames() }.toTypedArray())
        answered.await()
        return permissions.associateWith { check(it) }
    }

    override fun openSettings() {
        val intent = Intent(
            Settings.ACTION_APPLICATION_DETAILS_SETTINGS,
            Uri.fromParts("package", context.packageName, null),
        ).addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
        context.startActivity(intent)
    }

    private fun isGranted(name: String) =
        ContextCompat.checkSelfPermission(context, name) == PackageManager.PERMISSION_GRANTED

    private fun shouldShowRationale(names: List<String>): Boolean {
        val activity = activity ?: return false
        return names.any { ActivityCompat.shouldShowRequestPermissionRationale(activity, it) }
    }

    // Android 12 (API 31) gave Bluetooth its own runtime permissions. Before that, a BLE scan
    // needed fine location instead.
    private fun Permission.androidNames(): List<String> = when (this) {
        Permission.Bluetooth ->
            if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
                listOf(Manifest.permission.BLUETOOTH_SCAN, Manifest.permission.BLUETOOTH_CONNECT)
            } else {
                listOf(Manifest.permission.ACCESS_FINE_LOCATION)
            }
    }
}

// Fake: an outbound adapter written for tests, behind the PermissionChecker port. The test
// plays the OS and the user: it sets each status, and the answer the user gives a prompt.
class FakePermissionChecker : PermissionChecker {
    val statuses = mutableMapOf<Permission, PermissionStatus>()
    var answer = PermissionStatus.Granted
    val prompts = mutableListOf<List<Permission>>() // one entry per system prompt shown
    var settingsOpened = 0

    override fun check(permission: Permission): PermissionStatus =
        statuses[permission] ?: PermissionStatus.NotRequested

    override suspend fun request(permissions: List<Permission>): Map<Permission, PermissionStatus> {
        prompts += permissions
        permissions.forEach { statuses[it] = answer }
        return permissions.associateWith { answer }
    }

    override fun openSettings() {
        settingsOpened++
    }
}

    @Test

        os.statuses[Permission.Bluetooth] = PermissionStatus.Granted

        val result = permissions.request(listOf(Permission.Bluetooth))

        assertEquals(mapOf(Permission.Bluetooth to PermissionStatus.Granted), result)
        assertEquals(emptyList(), os.prompts)
    }

    @Test
    fun promptsWhenNotRequestedAndReturnsTheAnswer() = runTest {
        os.answer = PermissionStatus.Denied

        val result = permissions.request(listOf(Permission.Bluetooth))

        assertEquals(PermissionStatus.Denied, result[Permission.Bluetooth])
        assertEquals(listOf(listOf(Permission.Bluetooth)), os.prompts)
    }

    @Test
    fun promptsAgainAfterADenial() = runTest {
        os.statuses[Permission.Bluetooth] = PermissionStatus.Denied
        os.answer = PermissionStatus.Granted

        val result = permissions.request(listOf(Permission.Bluetooth))

        assertEquals(PermissionStatus.Granted, result[Permission.Bluetooth])
        assertEquals(1, os.prompts.size)
    }

    @Test
    fun neverPromptsWhenOnlySettingsCanChangeIt() = runTest {
        for (blocked in listOf(PermissionStatus.PermanentlyDenied, PermissionStatus.Restricted)) {
            os.statuses[Permission.Bluetooth] = blocked

        onAllow = viewModel::requestPermission,
        onOpenSettings = viewModel::openSettings,
        onDeviceClick = onDeviceClick,

        AlertDialog(
            onDismissRequest = viewModel::errorShown,
            confirmButton = { TextButton(onClick = viewModel::errorShown) { Text("OK") } },

            text = { Text(message) },

class DeviceListFragment : Fragment() {
    // Survives rotation and the trip to the detail screen; cleared when this
    // Fragment leaves the back stack for good.
    private val viewModel: DeviceListViewModel by viewModel()

    // Android lets only an Activity or a Fragment register for a result, and only while it is
    // being created, so the Fragment registers here and lends the launcher to the adapter.
    // It decides nothing: the adapter reads the answer.
    private val permissionChecker by lazy {
        (requireActivity().application as DeviceMonitorApplication).permissionChecker
    }
    private val permissionLauncher = registerForActivityResult(RequestMultiplePermissions()) {
        permissionChecker.onResult(requireActivity())
    }

    private var binding: FragmentDeviceListBinding? = null
    private var errorDialog: AlertDialog? = null
    private val adapter = DeviceAdapter { device ->
        val nav = findNavController()
        // A fast double tap delivers two clicks; only navigate from the list itself.
        if (nav.currentDestination?.id == R.id.deviceList) {
            nav.navigate(R.id.toDetail, Bundle().apply { putString("deviceId", device.id) })
        }
    }

    override fun onCreateView(inflater: LayoutInflater, container: ViewGroup?, savedInstanceState: Bundle?): View {
        val b = FragmentDeviceListBinding.inflate(inflater, container, false)
        binding = b
        b.deviceList.adapter = adapter
        b.deviceList.addItemDecoration(DividerItemDecoration(requireContext(), DividerItemDecoration.VERTICAL))
        b.scanButton.setOnClickListener { viewModel.startScan(b.filterInput.text.toString()) }
        return b.root
    }

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        viewLifecycleOwner.lifecycleScope.launch {
            viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.uiState.collect { render(it) }
            }
        }
    }

    override fun onStart() {
        super.onStart()
        permissionChecker.attach(requireActivity(), permissionLauncher)
    }

    // Back from Settings (or anywhere else): the permission may have changed.
    override fun onResume() {
        super.onResume()
        viewModel.refreshPermission()
    }

    override fun onStop() {
        permissionChecker.detach(permissionLauncher)
        super.onStop()
    }

    override fun onDestroyView() {
        super.onDestroyView()
        errorDialog?.dismiss() // a dismiss() doesn't call the cancel listener, so the error stays in state
        errorDialog = null
        binding?.deviceList?.adapter = null // the adapter outlives the view; don't let it keep the old list
        binding = null
    }

    // The one place that touches views: every new state ends here. The EditText keeps its
    // own text (and restores it after rotation), so render() never sets it.
    private fun render(state: DeviceListUiState) {
        val b = binding ?: return
        val isScanning = state.scan is ScanState.Scanning
        val devices = when (val scan = state.scan) {
            ScanState.Idle -> null
            is ScanState.Scanning -> scan.found
            is ScanState.Finished -> scan.found
        }
        renderPermission(b, state.bluetooth)
        b.scanButton.isEnabled = !isScanning && state.bluetooth == PermissionStatus.Granted
        b.progress.visibility = if (isScanning) View.VISIBLE else View.GONE
        b.statusText.text = when {
            isScanning -> "Scanning…"
            devices == null -> "Tap Scan to look for devices."
            devices.isEmpty() -> "No devices found. Try another filter."
            else -> "Devices found: ${devices.size}"
        }
        b.statusText.setTextColor(if (devices?.isEmpty() == true && !isScanning) Color.RED else Color.DKGRAY)
        adapter.submitList(devices.orEmpty())
        renderError(state.errorMessage)
    }

    // One message and at most one action per permission status.
    private fun renderPermission(b: FragmentDeviceListBinding, status: PermissionStatus) {
        val (message, action) = when (status) {
            PermissionStatus.Granted -> "Bluetooth permission: allowed" to null
            PermissionStatus.NotRequested ->
                "Device Monitor needs Bluetooth permission to find nearby devices." to "Allow Bluetooth"
            PermissionStatus.Denied ->
                "Bluetooth permission was denied. Scanning needs it to find nearby devices." to "Ask again"
            PermissionStatus.PermanentlyDenied ->
                "Bluetooth permission is off. You can turn it on in Settings." to "Open Settings"
            PermissionStatus.Restricted ->
                "Bluetooth is restricted on this device, so scanning isn't available." to null
        }
        b.permissionText.text = message
        val blocked = status != PermissionStatus.Granted && status != PermissionStatus.NotRequested
        b.permissionText.setTextColor(if (blocked) Color.RED else Color.DKGRAY)
        b.permissionButton.visibility = if (action == null) View.GONE else View.VISIBLE
        b.permissionButton.text = action
        b.permissionButton.setOnClickListener {
            if (status == PermissionStatus.PermanentlyDenied) {
                viewModel.openSettings()
            } else {
                viewModel.requestPermission()
            }
        }
    }

    private fun renderError(message: String?) {
        if (message == null) {
            errorDialog?.dismiss()
            errorDialog = null
        } else if (errorDialog == null) {
            errorDialog = AlertDialog.Builder(requireContext())
                .setTitle("Scan failed")
                .setMessage(message)
                .setPositiveButton("OK") { _, _ -> viewModel.errorShown() }
                .setOnCancelListener { viewModel.errorShown() }
                .show()
        }
    }
}

// Outbound adapter: Bluetooth permission on iOS, behind the Kotlin PermissionChecker port.
// iOS has one Bluetooth permission. Reading CBManager.authorization never prompts; the
// prompt appears when the app first uses Bluetooth, here by creating a CBCentralManager.
@MainActor
final class IosPermissionChecker: NSObject, @preconcurrency PermissionChecker,
    @preconcurrency CBCentralManagerDelegate {
    private var manager: CBCentralManager?
    private var waiting: [CheckedContinuation<Void, Never>] = []

    func check(permission: Permission) -> PermissionStatus {
        Self.bluetoothStatus()
    }

    // The Kotlin suspend fun. SKIE keeps the name `request` for the async function Swift
    // calls, so the one Swift implements is `__request`.
    func __request(permissions: [Permission]) async throws -> [Permission: PermissionStatus] {
        if CBManager.authorization == .notDetermined {
            await withCheckedContinuation { continuation in
                waiting.append(continuation)
                if manager == nil {
                    manager = CBCentralManager(
                        delegate: self, queue: nil,
                        options: [CBCentralManagerOptionShowPowerAlertKey: false]
                    )
                }
            }
        }
        let status = Self.bluetoothStatus()
        return Dictionary(uniqueKeysWithValues: permissions.map { ($0, status) })
    }

    func openSettings() {
        guard let url = URL(string: UIApplication.openSettingsURLString) else { return }
        UIApplication.shared.open(url)
    }

    // Called on the main queue (queue: nil) whenever the manager's state changes, including
    // once the user has answered the prompt.
    func centralManagerDidUpdateState(_ central: CBCentralManager) {
        guard CBManager.authorization != .notDetermined else { return }
        manager = nil
        let answered = waiting
        waiting = []
        answered.forEach { $0.resume() }
    }

    private static func bluetoothStatus() -> PermissionStatus {
        switch CBManager.authorization {
        case .notDetermined: .notRequested
        case .restricted: .restricted
        case .denied: .permanentlyDenied // iOS never shows the prompt again
        case .allowedAlways: .granted
        @unknown default: .restricted
        }
    }
}

final class DeviceListViewController: UIViewController, UITableViewDelegate {
    private let owner = ViewModelOwner()
    private lazy var viewModel: DeviceListViewModel = owner.viewModel()
    private var observation: Task<Void, Never>?

    private let filterField = UITextField()

    private let scanButton = UIButton(configuration: .filled())
    private let spinner = UIActivityIndicatorView(style: .medium)
    private let statusLabel = UILabel()
    private let tableView = UITableView()
    private lazy var dataSource = UITableViewDiffableDataSource<Int, String>(tableView: tableView) {
        tableView, indexPath, deviceId in
        let cell = tableView.dequeueReusableCell(withIdentifier: "device", for: indexPath)
        var content = UIListContentConfiguration.subtitleCell()
        if let device = SampleDevices.shared.find(id: deviceId) {
            content.text = device.name
            content.secondaryText = "\(device.id)   \(device.rssi) dBm"
        }
        cell.contentConfiguration = content
        cell.accessoryType = .disclosureIndicator
        return cell
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        title = "Device Monitor"
        navigationController?.navigationBar.prefersLargeTitles = true
        view.backgroundColor = .systemBackground

        filterField.placeholder = "Device name filter"
        filterField.borderStyle = .roundedRect
        filterField.autocorrectionType = .no
        scanButton.configuration?.title = "Scan"
        scanButton.addAction(UIAction { [weak self] _ in
            guard let self else { return }
            viewModel.startScan(filter: filterField.text ?? "")
        }, for: .touchUpInside)
        permissionLabel.numberOfLines = 0
        permissionLabel.font = .preferredFont(forTextStyle: .callout)
        permissionButton.contentHorizontalAlignment = .leading
        permissionButton.addAction(UIAction { [weak self] _ in
            guard let self else { return }
            if viewModel.uiState.value.bluetooth == .permanentlyDenied {
                viewModel.openSettings()
            } else {
                viewModel.requestPermission()
            }
        }, for: .touchUpInside)
        statusLabel.numberOfLines = 0
        tableView.register(UITableViewCell.self, forCellReuseIdentifier: "device")
        tableView.delegate = self

        let statusRow = UIStackView(arrangedSubviews: [spinner, statusLabel])
        statusRow.spacing = 8
        let permissionRow = UIStackView(arrangedSubviews: [permissionLabel, permissionButton])
        permissionRow.axis = .vertical
        permissionRow.alignment = .leading
        let stack = UIStackView(arrangedSubviews: [filterField, permissionRow, scanButton, statusRow, tableView])
        stack.axis = .vertical
        stack.spacing = 12
        stack.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(stack)
        NSLayoutConstraint.activate([
            stack.topAnchor.constraint(equalTo: view.layoutMarginsGuide.topAnchor),
            stack.leadingAnchor.constraint(equalTo: view.layoutMarginsGuide.leadingAnchor),
            stack.trailingAnchor.constraint(equalTo: view.layoutMarginsGuide.trailingAnchor),
            stack.bottomAnchor.constraint(equalTo: view.bottomAnchor),
        ])
        render(viewModel.uiState.value)
        // Back from Settings (or anywhere else): the permission may have changed.
        NotificationCenter.default.addObserver(
            self, selector: #selector(sceneDidActivate),
            name: UIScene.didActivateNotification, object: nil
        )
    }

    @objc private func sceneDidActivate() {
        viewModel.refreshPermission()
    }

    // Collect only while on screen, like repeatOnLifecycle(STARTED) on Android.
    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        observation?.cancel()
        observation = Task {
            for await state in viewModel.uiState {
                render(state)
            }
        }
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        observation?.cancel()
        observation = nil
    }

    // The one place that touches views: every new state ends here. The text field owns
    // its own text, so render() never sets it.
    private func render(_ state: DeviceListUiState) {
        let isScanning = state.scan is ScanStateScanning
        // SKIE turns the sealed interface into a Swift enum, so this switch is exhaustive.
        let devices: [Device]? = switch onEnum(of: state.scan) {
        case .idle: nil
        case .scanning(let scanning): scanning.found
        case .finished(let finished): finished.found
        }
        renderPermission(state.bluetooth)
        scanButton.isEnabled = !isScanning && state.bluetooth == .granted
        if isScanning { spinner.startAnimating() } else { spinner.stopAnimating() }
        spinner.isHidden = !isScanning
        if isScanning {
            statusLabel.text = "Scanning…"
        } else if let devices {
            statusLabel.text = devices.isEmpty
                ? "No devices found. Try another filter."
                : "Devices found: \(devices.count)"
        } else {
            statusLabel.text = "Tap Scan to look for devices."
        }
        statusLabel.textColor = devices?.isEmpty == true && !isScanning ? .systemRed : .label

        var snapshot = NSDiffableDataSourceSnapshot<Int, String>()
        snapshot.appendSections([0])
        snapshot.appendItems((devices ?? []).map(\.id))
        dataSource.apply(snapshot, animatingDifferences: true)
        renderError(state.errorMessage)
    }

    // One message and at most one action per permission status. SKIE makes the Kotlin enum a
    // Swift enum, so this switch is exhaustive.
    private func renderPermission(_ status: PermissionStatus) {
        let (message, action): (String, String?) = switch status {
        case .granted: ("Bluetooth permission: allowed", nil)
        case .notRequested: ("Device Monitor needs Bluetooth permission to find nearby devices.", "Allow Bluetooth")
        case .denied: ("Bluetooth permission was denied. Scanning needs it to find nearby devices.", "Ask again")
        case .permanentlyDenied: ("Bluetooth permission is off. You can turn it on in Settings.", "Open Settings")
        case .restricted: ("Bluetooth is restricted on this device, so scanning isn't available.", nil)
        }
        permissionLabel.text = message
        permissionLabel.textColor = switch status {
        case .granted: .secondaryLabel
        case .notRequested: .label
        case .denied, .permanentlyDenied, .restricted: .systemRed
        }
        permissionButton.configuration?.title = action
        permissionButton.isHidden = action == nil
    }

    private func renderError(_ message: String?) {
        guard let message, presentedViewController == nil else { return }
        let alert = UIAlertController(title: "Scan failed", message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "OK", style: .default) { [weak self] _ in
            self?.viewModel.errorShown()
        })
        present(alert, animated: true)
    }

    func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        tableView.deselectRow(at: indexPath, animated: true)
        guard let deviceId = dataSource.itemIdentifier(for: indexPath) else { return }
        navigationController?.pushViewController(DeviceDetailViewController(deviceId: deviceId), animated: true)
    }
}
