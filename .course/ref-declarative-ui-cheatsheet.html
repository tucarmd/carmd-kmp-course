Declarative UI Across Four Tracks

Compressed from Lesson 06 and Lesson 07. Built and checked with Compose BOM 2026.09.00, Navigation 2.10.2, AGP 9.4.1, Xcode 26.2 (Swift 6 mode).

The three rules

  1. UI = f(state). Change state, never widgets.
  2. Single source of truth. Each value lives in one place; pass it down, send events up.
  3. Derive, don't store. Status text, enabled flags and error colours are computed from state on every render.

Imperative tracks (XML, UIKit) follow the same rules by hand: state in a few properties, and one render() that sets every widget from them. Every handler ends with render().

Running work (a coroutine, a scan) is cancelled by Android rotation no matter what you save. Long-lived operations belong in a ViewModel (Lesson 08 cheatsheet).

Observing a source of state (Lesson 08)

An imperative toolkit is pushed updates (a delegate, callback or listener) and copies them into widgets. A declarative one observes a state source and re-renders.

Composeval state by vm.uiState.collectAsStateWithLifecycle(): a StateFlow becomes Compose State

SwiftUIan @Observable object's properties, or .task { for await s in flow { state = s } }
UIKita delegate/callback that calls render(), or Task { for await s in flow { render(s) } }

Routes carry ids, not objects; the destination looks the object up. Compose routes are @Serializable (serialization plugin + kotlinx-serialization-core). A fast double tap navigates twice: wrap a Compose on-screen Back in dropUnlessResumed { } (else a blank screen); in Fragments check currentDestination?.id before navigate/popBackStack (else an IllegalArgumentException on the next tap).

Traps

  • SwiftUI: .frame(maxWidth: .infinity) goes on the button's label, not the Button.
  • XML: fitsSystemWindows on a FragmentContainerView is ignored; put it on a wrapping FrameLayout.
  • XML: nullable binding; set recyclerView.adapter = null in onDestroyView when the adapter is a Fragment field.
  • XML: AppCompat buttons show their text in caps (tests see "SCAN").
